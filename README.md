# Fullstack Todo Ecosystem: Clean Architecture & Custom Router Engine

**Fullstack Todo Ecosystem** — это образовательный fullstack проект, разработанный с целью глубокого погружения в архитектуру программного обеспечения. Проект состоит из двух взаимосвязанных частей: **Клиентского приложения** (реализация Clean Architecture) и **Backend Framework** (кастомный роутер MiniExpress).

## Архитектурный подход
Проект реализует принципы **Clean Architecture**, полностью разделяя бизнес-логику от UI и базы данных. Я написал эту архитектуру, чтобы понять, как масштабировать приложения без "спагетти-кода".

### Слои приложения:
1.  **Domain Layer**: Чистые объекты и сущности (Business Logic), независимые от фреймворков.
2.  **Use Case Layer**: Инкапсуляция бизнес-правил (Create Todo, Delete Todo).
3.  **Repository Interface**: Адаптеры для работы с данными (In-Memory → SQLite).
4.  **UI Layer**: Фронтенд, связывающий данные с интерфейсом через кастомный State Manager.

## Ключевые достижения и технологии

### 1. Frontend: Чистая Архитектура & Состояние
*   **Custom State Manager**: Написан собственное решение для управления состоянием приложения (вместо Redux/Context), что позволило снизить зависимость от готовых библиотек и понять механику реактивности.
*   **Repository Pattern**: Реализована абстракция над данными. UI не знает, работает ли он с `localStorage`, массивом или SQL-базой.
*   **Dependency Injection**: Связи между слоями (например, Use Case ← Repository) управляются через внедрение зависимостей.

### 2. Тестирование:
*   **Vitest + Mocking**: Полное покрытие модульных тестов.
*   **Fake Repositories**: Использование фейковых репозиториев для изоляции логики от БД при тестировании Use Cases.
*   **Data Fixtures**: Генерация тестовых данных без реальных запросов к базе, что ускоряет CI/CD процессы.

### 3. Backend: MiniExpress Framework (Собственный роутер)
Поскольку готовый Express не давал полного контроля над HTTP-процессом, я создал собственный микро-фреймворк `MiniExpress`.
*   **Zero-Dependencies Engine**: Роутер написан на чистом Node.js (`http` module).
*   **Dynamic Routing & Security**: Поддержка путей вида `/todos/:id` с экранированием спецсимволов для защиты от **Regex Injection**.
*   **Functional Programming**: Архитектура роутера построена на Factory Functions и замыканиях, что упрощает тестирование и рефакторинг.
*   **Type-Safe API**: Строгая типизация запросов (`req.params`, `req.body`) через TypeScript.

## Структура проекта (Схема)
```text
├── Domain/          # Бизнес-объекты (Todo, ID)
├── UseCase/         # Логика создания/удаления
├── Repository/      # Интерфейсы и реализация (SQLite/Fake)
├── UI/              # Компоненты и кастомный Store
├── MiniExpress/     # Кастомный бэкенд-фреймворк
│   ├── Router/      # Логика сопоставления URL и RegExp
│   ├── Middleware/  # Обработка body, error handling
│   └── Handlers/    # API конечные точки
└── Tests/           # Unit tests с Vitest + Fake Data

```

Как запустить проект
# Установка зависимостей
npm install

# Запуск сервера бэкенда (MiniExpress)
npm run server

# Запуск тестов (проверка чистоты логики через Vitest)
npm run test


Чему я научился в процессе:
Архитектура: Как изолировать бизнес-логику от UI и почему это важно.
Тестирование: Как писать тесты, которые не зависят от БД (Mocking).
Безопасность: Понимание уязвимостей на уровне кода (Regex Injection, SQL Injection).
Deep Dive: Написание собственного роутера показывает глубокое понимание HTTP-протокола и работы серверной части Node.js.
